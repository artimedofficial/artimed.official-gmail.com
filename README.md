# Hoard & Hold — เกมเอาชีวิตรอดจากซอมบี้ (Phase 1 + 2B)

เกม 3 มิติแบบไฟล์เดียว `hoard-and-hold.html`: ดับเบิลคลิกเปิดได้เลยจาก `file://` ไม่ต้องติดตั้งหรือต่ออินเทอร์เน็ต เพราะฝัง Three.js r170 ไว้ในไฟล์แล้ว UI เป็นภาษาไทยทั้งหมด

Build ปัจจุบันคือ **2B.0.1**: Phase 1 ครบ (1A–1D) และเพิ่มชุด 2B คือจัดบ้านอิสระ, สภาพอากาศและน้ำ, ปลูกผัก

---

## 1. วิธีเล่น / วิธี Build

| งาน | คำสั่ง |
|---|---|
| เล่น | เปิด `hoard-and-hold.html` ด้วย Chrome / Edge / Firefox (ต้องรองรับ WebGL 2) |
| Build ใหม่จากซอร์ส | `npm install` แล้วตามด้วย `node tools/build.mjs` |
| ทดสอบ | `node tests/<ชื่อ>.mjs` (ใช้ Playwright + Chromium) |

ขั้นตอน build:

1. รวมไฟล์ `src/NN-*.js` ตามลำดับเลข
2. ตรวจ syntax ด้วย `node --check`
3. ฝัง bundle Three.js ลงใน `src/template.html`

ถ้าเครื่องไม่รองรับ WebGL เกมจะขึ้นข้อความแจ้งเป็นภาษาไทยแทนการค้าง

## 4. รูปแบบการบันทึก

ตั้งแต่ 2B เฟอร์นิเจอร์ในบ้านเก็บ `water: {l, raw}` (ถังน้ำ) และ `farm: {plots[], moist}` (แปลงผัก) และมี `home.boiled` กับ `flags.wxForce` (ดีบัก) เพิ่มมา ไฟล์ save เก่าโหลดได้เพราะ Sanitize จะเติมค่าเริ่มต้นให้

| ประเภท | คีย์ใน `localStorage` | เนื้อหา |
|---|---|---|
| รอบเล่น (run) | `hoardhold.run.v1` | ตัวละคร, บ้าน, โลก, เวลา, RNG |
| โปรไฟล์ | `hoardhold.profile.v1` | ทักษะสะสม, บันทึกชีวิต, การตั้งค่า |

- **ส่งออก/นำเข้า:** ทำได้จากเมนูหยุดเกม ได้ไฟล์ `.json`
- **Sanitizer:** ทุกครั้งที่โหลดจะผ่าน `Sanitize` ซึ่งเติมค่าที่ขาดและแทนค่าที่ผิดชนิด ทำให้ไฟล์ save เก่าหรือเสียยังเล่นต่อได้
- **RNG:** แยกเป็น stream (world / events / combat) และบันทึกจำนวนครั้งที่เรียกไว้ จึงเล่นซ้ำได้เหมือนเดิม

## 5. ข้อจำกัดที่ทราบ (Known limitations)

- **ประสิทธิภาพ:** ตัวเลข FPS ที่รายงานวัดบน SwiftShader (render ด้วย CPU ในเซิร์ฟเวอร์ทดสอบ) ยังไม่ได้วัดบน GPU จริง
- **การจัดเฟอร์นิเจอร์ (2B):** ย้ายได้ทีละชิ้น, ของบนโต๊ะ (ไมโครเวฟ) และรถ/ต้นมะม่วงย้ายไม่ได้, การย้ายข้ามชั้นทำได้ทันที (ไม่ได้จำลองการแบกขึ้นบันได), ของที่สั่งส่งก่อนระบาดยังลงช่องที่กำหนดไว้ก่อน แล้วค่อยย้ายเองได้
- **น้ำ (2B):** ยังเติมน้ำใส่ขวดพกพาไม่ได้ (ดื่มได้ที่บ้านเท่านั้น), น้ำในครัวเรือน 12 ล./วันหมดแล้วยังไม่มีบทลงโทษด้านสุขอนามัย (รอ Phase 3)
- **ปลูกผัก (2B):** ยังไม่มีปุ๋ย/ศัตรูพืช/ไฟปลูกต้นไม้, เก็บเมล็ดจากผลผลิตไม่ได้ (เมล็ดได้จากร้านเท่านั้น)
- **เหตุการณ์สุ่ม:** ตอนนี้มีแค่ซอมบี้กลางถนนกับการปล้น ส่วนชุดเหตุการณ์สุ่มทั่วไปเลื่อนไป Phase 2
- **ประเภทซอมบี้:** มีแค่ 2 ชนิด (walker, runner) ชนิดอื่นตามสเปกอยู่ใน Phase 2
- **ทักษะ:** บางทักษะยังไม่มีผลต่อเกม (แสดงป้าย "Phase 2" ในหน้าทักษะ)
- **ปรับสมดุล:** อัตราเจอเหตุการณ์ การติดเชื้อ และความเร็วหิว ปรับจากการจำลองแบบ debug เท่านั้น ยังไม่ผ่านการเล่นจริงยาว ๆ
- **ขนาดไฟล์:** ประมาณ 1.4 MB ส่วนใหญ่เป็น Three.js

### ผลวัดประสิทธิภาพ (`tests/perf.mjs`, หน้าจอ 1366×768)

ทั้งหมดวัดบน SwiftShader ซึ่ง render ด้วย CPU ล้วน ค่า FPS จึงต่ำกว่าการ์ดจอจริงหลายสิบเท่า ตัวเลขที่ใช้ประเมินได้จริงคือจำนวน draw call และจำนวน triangle

| คุณภาพ | ฉาก | FPS (SwiftShader) | Draw calls | Triangles |
|---|---|---|---|---|
| Low | บ้าน | 3.0 | 256 | 44k |
| Low | ซูเปอร์มาร์เก็ต | 2.9 | 313 | 26k |
| Medium | บ้าน | 0.9 | 260 | 43k |
| Medium | ซูเปอร์มาร์เก็ต | 0.7 | 314 | 35k |
| High | บ้าน | 0.5 | 258 | 42k |
| High | ซูเปอร์มาร์เก็ต | 0.7 | 317 | 40k |

ปริมาณงานระดับนี้ (ต่ำกว่า ~320 draw call และ ~45k triangle) ถือว่าเบาสำหรับ GPU ทั่วไป แต่ยังต้องยืนยันด้วยการวัดบนเครื่องจริง

## 7. หมายเหตุการแก้บั๊กใน 2B

- ประตูห้องนอนเล็กชั้นบนและประตูห้องเก็บของชั้นบน**เดินผ่านไม่ได้มาตั้งแต่ Phase 1** เพราะช่องบันไดบังอยู่ ตรวจพบตอนสร้างระบบตรวจทางเดิน 2B จึงย้ายประตูห้องนอนเล็กขึ้นไปทางเหนือ และย้ายประตูห้องเก็บของให้เปิดจากห้องนอนเล็กแทน

## 8. ขั้นต่อไป (Phase 2)

1. ระบบเหตุการณ์สุ่ม (event pool) พร้อมทางเลือกที่แสดงผลลัพธ์เป็นตัวเลข
2. ~~จัดเฟอร์นิเจอร์อิสระ และดัดแปลงบ้าน (ปลูกผัก เก็บน้ำฝน)~~ — เสร็จใน 2B
3. ถนอมอาหาร (ตากแห้ง หมักดอง) เพื่อใช้ผลผลิตจากสวนที่เน่าเร็ว และกรอกน้ำใส่ขวดพกพา
4. ซอมบี้ชนิดใหม่ และการบุกบ้านเป็นระลอก
5. วัดประสิทธิภาพบน GPU จริง และปรับ LOD
